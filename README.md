# SAROTECH Launcher v1.0.2

Independent Rust-first Android launcher foundation.

## Frozen architecture
- Native Android UI: Kotlin + Jetpack Compose
- Domain/search core: Rust
- Android bridge: JNI
- Minimum Android: API 29 (Android 10)
- Compile / target SDK: 35
- JDK: 17
- Android Gradle Plugin: 8.7.3
- Gradle: 8.9
- Android NDK: 27.2.12479018
- ABI targets: arm64-v8a, armeabi-v7a, x86_64
- No ads, analytics, tracking, mandatory account, or runtime network dependency in this foundation.

## Build in GitHub Actions
The workflow installs the pinned toolchain, runs Rust tests, builds the JNI libraries, then builds debug and unsigned release APKs.

## Local build
Requirements: JDK 17, Android SDK 35, Android NDK 27.2.12479018, Rust stable, cargo-ndk, Gradle 8.9.

```bash
cargo generate-lockfile
cargo test --workspace --locked

export ANDROID_NDK_HOME="$ANDROID_SDK_ROOT/ndk/27.2.12479018"
export ANDROID_NDK_ROOT="$ANDROID_NDK_HOME"

cargo ndk -t arm64-v8a -t armeabi-v7a -t x86_64 \
  -o app/src/main/jniLibs build --release -p sarotech-android-bridge --locked

gradle assembleDebug
```

## Implemented in this foundation
- Android HOME and app-launcher entry points.
- Scoped launcher intent package visibility.
- App discovery and exact Activity component launching.
- Rust-backed normalization and sorting through JNI.
- JNI load fallback for local UI development.
- Separate repository and ViewModel.
- DataStore theme/haptics settings repository foundation.
- Minimal clock/home and app drawer search.
- Follow System theme as default, with temporary local theme override.
- Package change receiver contract and resume refresh.
- Resource strings, theme, and original vector launcher icon.
- R8 rules for JNI method preservation.
- Rust unit tests, Kotlin unit tests, Android instrumentation smoke test.
- CI workflow for Rust and Android builds.

## Not yet complete
This is an engineering foundation, not a feature-complete premium launcher. Favorites/folders persistence, five full home styles, widget host, icon packs, profiles, focus/Pomodoro UI, usage tracking, app blocking, website controls, full backup/restore and notification dots still require implementation and device testing.

## Release signing
The CI release APK is unsigned. For distribution, configure a private keystore using GitHub Actions secrets or local secure signing properties. Never commit keystores or passwords.

## Gradle Wrapper note
`gradle-wrapper.properties` pins Gradle 8.9. The binary `gradle-wrapper.jar` and generated `gradlew` scripts are not included in this archive because they must be generated by the official Gradle wrapper task, not fabricated. On a machine with Gradle 8.9 installed, run:

```bash
gradle wrapper --gradle-version 8.9
```

Then commit `gradlew`, `gradlew.bat`, and `gradle/wrapper/gradle-wrapper.jar`.
